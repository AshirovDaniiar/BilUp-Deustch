## 2. Kyrgyz localization and Russian leakage

### Verified coverage

The Russian dictionary has **280 keys**. `src/i18n/ky.ts` explicitly overrides **121** of them; the remaining **159 (56.8%)** inherit Russian through `...ru`. The file comment and `src/i18n/index.ts:9` confirm that missing values silently fall back. The often-quoted 43% coverage is therefore a valid key-override ratio, but it is not a quality score or proof every override is linguistically correct.

Data counts were computed from the current TypeScript modules: 226/226 vocabulary items have a Kyrgyz meaning field (29 have identical RU/KY values, which require human review but are not automatically wrong); none have a distinct Kyrgyz example translation because the vocabulary schema stores `exampleRu` only. All 20 grammar concepts have some KY title/summary/why/discover strings, but **0/70** individual “when” notes and **0/40** grammar-mistake notes have KY. **0/202** exercise explanations and **0/86** listening dialogue lines have KY. Thus the first audit's substance is right; it understated the counted number of “when” entries by describing them as 20 lists. Reading glosses have ru/ky fields, while the surrounding passages/questions are German and quiz explanations remain Russian-keyed. These counts establish field coverage, not translation correctness.

## 5. Responsive design, touch targets, accessibility

### Independent browser check

The existing build was served without rebuilding. Chrome device metrics showed these shell modes: at **390×844 DPR 3** and **768×1024 DPR 2**, the sidebar computed to `display:none` and the bottom navigation to `display:grid`; at **1440×900 DPR 1**, the sidebar was `flex` and bottom navigation `none`. The home-route document width matched viewport width at all three checks (390, 768, and 1425 CSS px respectively; 1425 is the 1440 viewport less the scrollbar). Reading route document/body widths matched 390 and 768. This verifies the main shell at those sizes, not every route or interaction claimed in the supplied audit.

At 390 and 768, Reading rendered 40 tappable word buttons; the first measured **53×41 CSS px**, below a 44 px target height. The Home route had three interactive targets under 44 px at 390/768; desktop Home had none below that cutoff. Source defines `.iconbtn` as 40×40 in `src/styles/base.css:91`. These are concrete touch-target risks. The 1024 px breakpoint, not a tablet-specific rule, switches to sidebar in `src/styles/base.css:93-108`; portrait tablet uses the mobile shell stretched to tablet width.

## 7. Important issues not fully surfaced in the supplied audit

1. **Reading results are mislabeled as grammar mistakes.** `src/features/reading/ReadingLab.tsx:53` maps reading questions to `kind: 'grammar'` and uses the entire passage as `why: { ru: text.body.join(' ') }`. Wrong answers may pollute grammar mistake history, and feedback can repeat the whole passage instead of an explanation. Use a reading mistake kind and per-question rationale.
2. **The default profile greets users as Daniiar.** `src/app/store.tsx:11-13` sets `name: 'Daniiar'`. This is visible on first launch and is confusing for every other learner. Default to an empty/localized name or provide onboarding.
3. **Placement output exceeds the available curriculum evidence.** `src/screens/PracticeScreens.tsx:127-128` can recommend A2 based on a raw percentage, while `src/screens/LearnScreen.tsx:21-46` exposes only A1 and tells users higher levels are locked. The placement result is not calibrated to visible course availability. Label it as a rough result or align it with available validated content.
4. **Tutor pending quiz state survives chat reset.** `src/services/tutor.ts:43,65-78` stores one module-level pending answer; clearing persisted chat in `src/features/ai/TutorChat.tsx` does not clear it. An unrelated next message can be evaluated against stale quiz context. Scope pending state per conversation and reset it with that conversation.
5. **Reading translation display ignores the selected locale.** `src/features/reading/ReadingLab.tsx:95-104` displays Russian and Kyrgyz together when a gloss is opened rather than selecting the chosen explanation locale; this undercuts the language setting even where both values exist.

Other concerns in the supplied report were confirmed: hard-coded default brand/name strings, localized ARIA gaps, incomplete Kyrgyz content, and heuristic rather than validated assessment. Contrast ratios and real-device behavior were not independently measured here.

## Top 10 verified issues

1. **Language preferences and content schema conflate UI/explanation/target language** — `types.ts`, `store.tsx`, `ProfileScreen.tsx`, speech service.
2. **Kyrgyz UI and instructional content have large silent gaps** — 121/280 UI key overrides; 0/202 exercise rationales and 0/40 grammar mistake-note translations.
3. **Russian prose bypasses locale selection** — quiz prompts, tutor, analysis, vocab, reading/listening explanations.
4. **XP can be repeatedly earned; unit test completion has no pass threshold** — QuizRunner, WritingLab, SpeakingLab, PracticeScreens.
5. **Unvalidated localStorage blob has no schema migration/recovery** — store.tsx.
6. **Unit 10 cannot reach full section completion because no unit-10 reading exists** — data/reading.ts, UnitScreen.tsx, stats.ts.
7. **Study time counts visible idle time and triggers whole-provider updates/writes** — store.tsx.
8. **Tablet portrait uses phone navigation; touch targets fall below 44 px** — Layout/CSS and measured Reading/Home elements.
9. **No PWA manifest, service worker, or offline/install behavior** — public, index.html, vite.config.ts.
10. **No automated tests, lint, formatter, or CI** — package scripts/config; only typecheck/build scripts are present.

## Top 5 architectural recommendations

1. Establish distinct UI locale, explanation locale, target language, and course ID; register language packs instead of hard-coded language fields.
2. Centralize completion, score, XP, and mastery changes in an idempotent activity-result/event model with course-scoped IDs.
3. Move persistence behind a versioned/validated repository interface, retaining local storage initially and adding recovery/export.
4. Preserve React/TypeScript/Vite and evolve content schemas/services; add content validation and localization coverage gates.
5. Add tested responsive/PWA platform boundaries after stabilizing the product model; use route-level splitting when bundle growth warrants it.

## Rewrite decision and first milestone

**Incremental refactoring is preferable to a rewrite.** The current UI/content separation, typed activity data, lesson flow, SRS, design primitives, and strict TypeScript baseline have real reuse value. The required changes are concentrated in language/course modeling, progress rules, and persistence, not a failing framework or unmaintainable total codebase.

**Recommended first implementation milestone: Progress integrity and recoverable persistence.** Define the activity result contract and idempotency policy; fix test pass semantics and repeat XP; fix unit-10 reading availability/progress denominator; add storage schema validation/migration and tests. This prevents corrupt or misleading learner history while the language-model work is designed. In parallel, specify the separate locale/target/course schema before authoring English or expanding Kyrgyz content.
